# Producer 
Event Producer - отправляет событие о записи нового рецепта (POST /api/v2/recipe). Для гарантии `at-least-once` придется делать простенький transactional outbox, а CDC не попадает под условия ЛР - реализовать простой producer.

# Consumer
Consumer - читатет события о добавлении нового рецепта. Кладет в базу для чтения. Консьюмер идемпотентный, так как передается id

# События
См. [event_catalog.md](/lab-6/event_catalog.md)

# Гарантии доставки
Гарантия at-leat-once. На продюсере достигается путем transactional outbox. На консьюмере с помощью manaul ack.

Чтобы события не терялись на продюсере, необходимо реализовать transactional outbox.

Поток событий для создания рецепта
```
1. User -> POST /api/v2/recipe
2. /api/v2/recipe hander -> процесс сохранения данных
3. job publisher(producer) -> читает данные из outbox таблицы и пишет событие в Кроля
4. CreateRecipeConsumer -> читает данные из очереди и пишет данные в отдельную таблицу
5. User -> GET /api/v2/recipes  читает обновленные данные или старые, если консьюмер не успел вычитать сообщение
5. User -> GET /api/v2/recipes  читает обновленные данные или старые, если консьюмер не успел вычитать сообщение
```
